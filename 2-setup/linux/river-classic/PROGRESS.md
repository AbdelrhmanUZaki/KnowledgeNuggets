- (17) **touchpad gestures + true 3-finger right click** (user round: 3-finger tap back, 4-finger tap forward, 3-finger swipe volume, 3-finger press = right click):
  - **Why the obvious design is wrong**: `riverctl input '*Touchpad' click-method none` does **not** stop physical clicks — libinput's own docs say "no effect on events generated by physical buttons" and it still forwards the clickpad's BTN_LEFT. A daemon that sets `none` and injects clicks would double every press. libinput also **ignores every non-left button on a clickpad** (`tp_process_button`), so forwarding a synthetic BTN_RIGHT does not work either.
  - **Chosen design**: `config/river/gestures.py` mirrors the pad as a **non-clickpad uinput touchpad**. The clone copies every capability, absinfo and property **except `INPUT_PROP_BUTTONPAD`**, and reuses the physical name/IDs, so libinput sees an ordinary touchpad: acceleration, palm rejection, DWT, tap-to-click, 2-finger scrolling and tap-and-drag all still run. The daemon reads the physical pad raw, translates a physical press to **1 finger = left, 2/3+ fingers = right**, and forwards everything else (MT slots, pressure/size, SYN) untouched. It `EVIOCGRAB`s the physical pad only **after** river adopts the clone (`riverctl list-inputs` shows a second `...Touchpad`). On any exit the fd closes, the kernel drops the grab and the clone disappears → stock clickfinger is back; there is no dead-touchpad failure mode.
  - **Taps / swipes**: raw MT engine with `python3 gestures.py --selftest` (11 cases, all pass): 3-finger tap → BTN_SIDE (back), 4-finger tap → BTN_EXTRA (forward), 3-finger swipe up/down → `wpctl set-volume @DEFAULT_AUDIO_SINK@ 3%±` (one step per 8% of pad height, 1.6:1 vertical lock, 40 ms throttle). 1/2-finger taps stay libinput's job. Documented side effect: libinput still emits its own **middle click on a 3-finger tap** in addition to back; removing it would mean reimplementing palm rejection and tap-and-drag, a worse trade.
  - **udev**: new `udev/70-river-classic-input.rules` (touchpad event nodes → group `plugdev`, 0660; `/dev/uinput` → `plugdev` 0660 + `static_node=uinput`). logind's uaccess ACL covers the active seat's input nodes but **not** `/dev/uinput` (subsystem `misc`), and this daemon opens evdev directly (river itself uses libseat). `install.sh` gained a `rules` phase; `restore.sh` chmods all `*.py`.
