- (17) **touchpad gestures + true 3-finger right click** (user round: 3-finger tap back, 4-finger tap forward, 3-finger swipe volume, 3-finger press = right click):
  - **Why the obvious design is wrong**: `riverctl input '*Touchpad' click-method none` does **not** stop physical clicks — libinput's own docs say "no effect on events generated by physical buttons" and it still forwards the clickpad's BTN_LEFT. A daemon that sets `none` and injects clicks would double every press. libinput also **ignores every non-left button on a clickpad** (`tp_process_button`), so forwarding a synthetic BTN_RIGHT does not work either.
  - **Chosen design**: `config/river/gestures.py` mirrors the pad as a **non-clickpad uinput touchpad**. The clone copies every capability, absinfo and property **except `INPUT_PROP_BUTTONPAD`**, and reuses the physical name/IDs, so libinput sees an ordinary touchpad: acceleration, palm rejection, DWT, tap-to-click, 2-finger scrolling and tap-and-drag all still run. The daemon reads the physical pad raw, translates a physical press to **1 finger = left, 2/3+ fingers = right**, and forwards everything else (MT slots, pressure/size, SYN) untouched. It `EVIOCGRAB`s the physical pad only **after** river adopts the clone (`riverctl list-inputs` shows a second `...Touchpad`). On any exit the fd closes, the kernel drops the grab and the clone disappears → stock clickfinger is back; there is no dead-touchpad failure mode.
  - **Taps / swipes**: raw MT engine with `python3 gestures.py --selftest` (11 cases, all pass): 3-finger tap → BTN_SIDE (back), 4-finger tap → BTN_EXTRA (forward), 3-finger swipe up/down → `wpctl set-volume @DEFAULT_AUDIO_SINK@ 3%±` (one step per 8% of pad height, 1.6:1 vertical lock, 40 ms throttle). 1/2-finger taps stay libinput's job. Documented side effect: libinput still emits its own **middle click on a 3-finger tap** in addition to back; removing it would mean reimplementing palm rejection and tap-and-drag, a worse trade.
  - **udev**: new `udev/70-river-classic-input.rules` (touchpad event nodes → group `plugdev`, 0660; `/dev/uinput` → `plugdev` 0660 + `static_node=uinput`). logind's uaccess ACL covers the active seat's input nodes but **not** `/dev/uinput` (subsystem `misc`), and this daemon opens evdev directly (river itself uses libseat). `install.sh` gained a `rules` phase; `restore.sh` chmods all `*.py`.

- (31) **clipboard popup instead of the full CopyQ window** (user round: "I want the copyq to be as a popup, not a full app when I open it, to be easy to paste directly"):

The full CopyQ window (images, pins, tags, editing, tabs) moves to `Super+Shift+V`/`Alt+Shift+V`. Verified end-to-end by injecting a real `Super+V` key event (uinput) and screenshotting: popup only, no main window, no tag switch.
  - **Wayland limitation confirmed by test**: selecting cannot auto-paste — `copyq paste()` fails with "Failed to get current window for pasting from clipboard" under river (and `tray_item_paste=true` silently fails the same way), so the flow is select → `Ctrl+V`. CopyQ simply cannot identify/inject into the target window on this compositor.
  - **CopyQ server dies silently in-session** (found while testing): the init-started server (08:07) was gone by 09:52 with no crash in the journal, no OOM, no exit line in its own log — and every restart the same day died the same way (one within ~6 s). The old binding self-healed via `--start-server toggle`, which masked it. The wrapper is self-healing the same way (`--start-server` + probe loop), **and hides the main window a fresh server start restores** before opening the menu — without that hide, a post-crash first press shows the full window behind the popup. Server starts from the wrapper are `setsid -f` so they survive short-lived parents.
  - Docs: README "Clipboard" section rewritten (popup vs full window), keybind tables updated.
  - **Speed round** (user round: "it takes around 1.5 seconds to open the popup, it should be instant"): measured — every `copyq` CLI call cost ~0.5 s with the server already up (the AppImage pays a FUSE mount + Qt startup per launch), and the wrapper made two calls (probe + eval). Fix, both sides: (1) the AppImage is now **extracted** to `~/.local/opt/copyq-17.0.0` and the `~/.local/bin/copyq` wrapper execs `AppRun` from there (falls back to the AppImage; `install-copyq17.sh` does the extraction on install) → ~0.1 s per CLI call; (2) `clipboard-menu.sh` is a **single round-trip**: `--start-server eval "if (visible()) hide(); menu(...)"` (no probe loop; the eval itself hides the window a fresh start restores). Verified: warm path 0.126 s end-to-end, cold path (server killed first) 0.45 s with the popup only, and a live injected `Super+V` shows just the popup.
  - **Popup leaked the full window on cold starts** (user round: "super+v opens the popup but also shows the original copyq window"): the server had died again, and a fresh start restores the main window *late* — later than both the wrapper's settle+hide and the eval's `visible()` check (a `kill -9` test reproduces it; a clean `copyq exit` restart does not, because the saved state says hidden). Fix: `menu()` first (popup is instant), then `hide()` repeated every ~300 ms for ~1.8 s server-side — `sleep()` runs off the UI thread, arrow-key navigation verified responsive mid-sleep. Warm path stays one plain `eval menu(...)` (~0.2 s, no window ever). After `kill -9`, screenshots at 1.1 s and 3.1 s show the popup only. Note: `copyq visible` reports unreliably (true while the window is actually hidden); the screenshot is the ground truth.
  - **Keep the server in the background** (user round: "how to open copyq in background? as if it's not opened, the popup will open it"): new `config/river/copyq-keepalive.sh`, started from init after `copyq-setup.sh` (killed by session-cleanup, PID file in `$STATE_DIR`, idempotent, 15 s interval). It probes `copyq count` and restarts a dead server detached + hidden (same repeated-hide settle as the popup wrapper), so the Super+V popup stays warm (~0.2 s) instead of paying the cold path after every silent server death. Verified live: `kill -9` the server → back up within one interval, no window on screen (screenshot), popup 0.216 s. Manual background start: `setsid -f ~/.local/bin/copyq --start-server`. Cleanup also gained the extracted-AppDir pattern (`pkill -f ~/.local/opt/copyq-1[7].*/AppRun`) — the old `pkill -x copyq` misses `AppRun.wrapped`.
